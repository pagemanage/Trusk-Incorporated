The File as a Resonant Body

Every binary file possesses a measurable body: its total size in bytes, the distribution of its segments, and the density of data within those segments. These physical properties are not merely technical metadata — they are acoustic potentials waiting to be awakened.

In this sonic digestion framework, file size and segment structure become the foundation for frequency-based music generation. Larger segments can oscillate at lower frequencies, denser regions produce higher partials, and the overall file size determines the fundamental tone or the duration of the entire composition.

Core Sonic Mappings: From Bytes to Frequencies

Fundamental Principles

  • Total File Size → determines the base frequency (fundamental) or the total duration of the piece.
  • Segment / Section Size → maps directly to oscillator frequencies or filter cutoffs.
  • Segment Offset → controls phase, delay time, or panning position.
  • Data Density & Entropy → influences harmonic richness and spectral brightness.
  • Number of Segments → defines polyphony (how many simultaneous voices).

Common Frequency Mapping Strategies

  1. Linear Mapping
    Frequency (Hz) = Base + (segment_size / total_size) × Range
    Example: A 64 KB segment in a 1 MB file might generate ~440 Hz (A4) while a 512 KB segment produces a deep sub-bass.
  2. Logarithmic / Musical Scaling
    Map byte sizes to MIDI notes or just intonation ratios. Large code segments become low drones; small symbol tables become high tinkling bells.
  3. Harmonic Series
    Treat segment sizes as multiples of a fundamental frequency derived from the file’s total size or magic number.
  4. Granular Frequency
    Small segments (under 4 KB) become grains whose playback rate equals their offset or size in Hz.

Segment Structure as Orchestral Sections

Binary files are rarely monolithic. They are divided into segments and sections, each with its own acoustic personality:

Segment / Section Type Typical Size Behavior Sonic Interpretation
.text / __TEXT (code) Medium to large, consistent Main melodic voice or harmonic drone
.data / __DATA (initialized data) Variable, often medium Rhythmic or textural layer
.bss / NOBITS (uninitialized) Large but zero-filled (low entropy) Pure sine tones or sub-bass resonance
.symtab / symbol table Small to medium, dense pointers Percussive clicks or high-frequency metallic tones
Raw / unknown chunks Arbitrary Granular cloud or noise bursts

The relative proportion of each segment within the whole file creates a unique spectral fingerprint — a sonic signature unique to that binary organism.

Practical Sonic Adaptation Techniques

1. Frequency from Segment Size

// Conceptual mapping (not executable code)
baseFreq = 55;                    // A1 as fundamental
freq     = baseFreq * (segment.size / totalSize * 8 + 1);

This produces a natural harmonic spread: larger segments sound deeper, smaller ones higher.

2. Multi-Voice Polyphony from Number of Segments

If a file contains 12 segments, spawn 12 parallel oscillators or voices. Each voice’s frequency is derived from its segment’s relative size, while its amplitude follows the segment’s entropy.

3. Temporal Structure from Offsets and Sizes

  • Segment offset → delay time or onset (in milliseconds or beats)
  • Segment size → note duration or loop length
  • Distance between segments → rhythmic gaps or polyrhythms

4. Spectral Content from Internal Data

Within each segment:

  • High entropy regions → rich, noisy harmonics or FM modulation depth
  • Low entropy (repetitive bytes) → clean sine waves or resonant filters
  • Byte value (0–255) → modulates frequency deviation or filter Q

Advanced Resonance Ideas

  • File Size as Macro Duration: A 4 MB binary becomes a 4-minute piece; each 64 KB block equals one second.
  • Self-Similar Fractal Mapping: Recursively analyze sub-segments so that smaller structures influence micro-variations inside longer tones.
  • Physical Modeling: Treat the entire file as a vibrating string or membrane whose length = total size and tension = average entropy.
  • Inter-File Harmony: Load multiple binaries simultaneously; their segment sizes create consonant or dissonant interval relationships.

Integration with the Universal Digestion Schema

The previously defined schema already contains all necessary elements:

  • metadata.size and metadata.entropy set global pitch and brightness.
  • structures.segments[] provides offset, size, and type for individual frequency voices.
  • structures.groups routes different segment types to different synthesis engines (logical → melodic, physical → bass, mechanical → percussion).

In Max/MSP this data flows naturally into poly~, cycle~, groove~, reson~, or granular engines, turning the binary’s anatomy into a living, frequency-rich soundscape.
